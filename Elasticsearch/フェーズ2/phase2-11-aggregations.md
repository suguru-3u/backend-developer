# 第11章　集計 ― Aggregations とファセット検索

> **視点を変える**
> ここまでは「条件に合う文書を1件ずつ探す」検索を扱ってきました。この章は視点が変わります。**「まとめて数える・集計する」**――カテゴリごとに何件あるか、価格の平均はいくらか、在庫はどれくらいか。ECサイトの左側にある絞り込みメニュー（ファセット）や、管理画面のダッシュボードは、この Aggregations（集計）で作られています。

---

## 学習目標

この章を終えると、次のことができるようになります。

- 集計が「検索結果の集合」に対して働くことを説明できる
- **メトリック集計**（avg / min / max / sum / stats / cardinality）で数値を要約できる
- **バケット集計**（terms / range / histogram）でデータをグループ分けできる
- 集計を**入れ子**にして「カテゴリ別の平均価格」のような多段集計ができる
- 検索クエリと集計を同時に実行し、`size: 0` でヒットを省いて集計だけ取得できる
- **ファセット検索**を実装し、`post_filter` で「絞り込みつつ他ファセットの件数を保つ」挙動を作れる
- 集計に `keyword` 型が要る理由（`text` の落とし穴）を説明できる

---

## この章のサンプルデータ（前提）

第8〜10章と同じ `products`（6件）を使います。集計で主役になるのは次のフィールドです。

| フィールド | 型 | 集計での役割 |
|---|---|---|
| `category` | `keyword` | terms 集計（カテゴリ別件数） |
| `tags` | `keyword`（配列） | terms 集計（タグ別件数） |
| `price` | `integer` | メトリック・range・histogram |
| `in_stock` | `boolean` | terms（在庫あり/なしの割合） |

（データ再掲：オーディオ2件・キッチン家電2件・パソコン1件・スポーツ1件。価格は 5,980〜128,000円。在庫は1件のみ false。）

---

## 11.1　集計とは ― 2つの種類

集計は、`_search` の中に `aggs`（`aggregations` の略）として書きます。**クエリで絞り込んだ文書集合**に対して働くのが重要なポイントです（クエリを省くと全件が対象）。

集計は大きく2種類あります。

```
┌────────────────────────────┬────────────────────────────────┐
│ メトリック集計              │ バケット集計                    │
│ (metrics)                  │ (bucket)                       │
│ 数値を「1つの値」に要約      │ 文書を「グループ」に振り分ける    │
│ 例: 平均価格 = 31,143円     │ 例: カテゴリ別に文書をまとめる    │
│ avg, min, max, sum, stats  │ terms, range, histogram, ...   │
└────────────────────────────┴────────────────────────────────┘
```

そして**バケットの中にさらに集計を入れ子**にできるのが、集計の強力なところです（例：「カテゴリ別（バケット）× 平均価格（メトリック）」）。

---

## 11.2　メトリック集計 ― 数値を要約する

`price` を要約してみます。ヒット文書は要らないので `size: 0` を付けます。

```json
GET /products/_search
{
  "size": 0,
  "aggs": {
    "avg_price":   { "avg":   { "field": "price" } },
    "max_price":   { "max":   { "field": "price" } },
    "price_stats": { "stats": { "field": "price" } }
  }
}
```

- `avg` / `min` / `max` / `sum`：それぞれ平均・最小・最大・合計。
- `stats`：count / min / max / avg / sum を一度に返す便利版。
- `cardinality`：**ユニーク数**（近似）。「カテゴリは何種類あるか」などに使う。

```json
"distinct_categories": { "cardinality": { "field": "category" } }
```

> `size: 0` を付けると、ヒット文書（`hits`）は空になり、`aggregations` だけが返ります。ダッシュボードのように集計値だけ欲しいときの定番です。

---

## 11.3　バケット集計 ― グループに分ける

### terms ― 値ごとにまとめる（ファセットの主役）

`category` の値ごとに文書数を数えます。

```json
GET /products/_search
{
  "size": 0,
  "aggs": {
    "by_category": {
      "terms": { "field": "category", "size": 10 }
    }
  }
}
```

結果は `オーディオ: 2`, `キッチン家電: 2`, `パソコン: 1`, `スポーツ: 1` のように、各バケットの `key` と `doc_count` が返ります。**`tags` は配列**なので、terms 集計すると各要素が個別にカウントされ、「防水: 3」「Bluetooth: 2」のようなタグ別集計になります。

> **重要：集計は `keyword` に対して行う**
> terms 集計の `field` には **`keyword` 型**を指定します。`text` 型はアナライザーで分割されるうえ、集計には `fielddata`（メモリ上のデータ構造）が必要で既定で無効です。うっかり `text` に集計をかけるとエラーになるか、大量メモリを消費します。だから第3章で `category` / `tags` を `keyword` にしておいたわけです。

### range ― 価格帯に分ける

数値を任意の区間で区切ります。ECの「〜5,000円／5,000〜20,000円／20,000円〜」のような価格帯フィルタが作れます。

```json
GET /products/_search
{
  "size": 0,
  "aggs": {
    "price_ranges": {
      "range": {
        "field": "price",
        "ranges": [
          { "to": 5000 },
          { "from": 5000, "to": 20000 },
          { "from": 20000 }
        ]
      }
    }
  }
}
```

各区間は `from`（以上）〜`to`（未満）です。

### histogram ― 等間隔で刻む

一定の幅で自動的にバケットを作ります。`interval` を指定します（日付なら `date_histogram` で「月別件数」なども作れます）。

```json
"price_histogram": {
  "histogram": { "field": "price", "interval": 10000 }
}
```

---

## 11.4　集計の入れ子 ― カテゴリ別の平均価格

バケットの中にメトリックを入れると、「グループごとの要約」が得られます。

```json
GET /products/_search
{
  "size": 0,
  "aggs": {
    "by_category": {
      "terms": { "field": "category" },
      "aggs": {
        "avg_price": { "avg": { "field": "price" } },
        "in_stock_count": {
          "filter": { "term": { "in_stock": true } }
        }
      }
    }
  }
}
```

これで各カテゴリのバケットの中に、`avg_price`（そのカテゴリの平均価格）と `in_stock_count`（在庫ありの件数）がぶら下がります。バケット→メトリックの入れ子は、集計の中で最も使うパターンです。

```
by_category (terms)
 ├─ オーディオ (doc_count: 2)
 │    ├─ avg_price: 9,390
 │    └─ in_stock_count: 2
 ├─ キッチン家電 (doc_count: 2)
 │    ├─ avg_price: 15,640
 │    └─ in_stock_count: 1
 └─ ...
```

---

## 11.5　ファセット検索 ― 検索と集計を同時に

ECサイトの検索結果画面は、「ヒット商品の一覧」と「絞り込みメニュー（カテゴリ別件数など）」を**同時に**表示します。これは、1回のリクエストで `query`（一覧用）と `aggs`（絞り込み用）を**両方**書けば実現できます。

```json
GET /products/_search
{
  "query": {
    "match": { "description": "防水" }
  },
  "aggs": {
    "by_category": { "terms": { "field": "category" } },
    "by_tags":     { "terms": { "field": "tags" } },
    "price_stats": { "stats": { "field": "price" } }
  }
}
```

ここで `size: 0` を**付けていない**ので、`hits`（防水にマッチした商品一覧）と `aggregations`（そのマッチ集合内でのカテゴリ別・タグ別の件数）が同時に返ります。**集計はクエリで絞られた集合に対して計算される**ため、件数は「防水の中での内訳」になります。

---

## 11.6　post_filter ― 絞り込みつつ、他ファセットの件数を保つ

ファセット検索には有名なジレンマがあります。ユーザーが「カテゴリ＝オーディオ」を選んだとき――

- **商品一覧**は「オーディオだけ」に絞りたい。
- でも**カテゴリのファセット件数**は、「オーディオを選んだ後」も他カテゴリの件数（パソコン: 1 など）を出したい。もし普通の `query` で絞ると、集計もオーディオだけになり、他カテゴリが消えてしまう。

これを解決するのが **`post_filter`** です。`post_filter` は**集計が計算された後**にヒットだけを絞り込みます。

```json
GET /products/_search
{
  "query": {
    "match": { "description": "防水" }
  },
  "aggs": {
    "by_category": { "terms": { "field": "category" } }
  },
  "post_filter": {
    "term": { "category": "オーディオ" }
  }
}
```

動きは次のとおりです。

```
1. query（防水）で集合を作る
2. aggs を計算  ← この時点では post_filter は未適用（全カテゴリの件数が出る）
3. post_filter（category=オーディオ）で hits だけ絞る
   → 一覧: オーディオのみ
   → ファセット件数: 防水の中の全カテゴリ内訳（他カテゴリも残る）
```

> **コラム：現場ではもう少し複雑**
> 「選択中のファセットだけ post_filter、他のファセットはそれぞれ別々に集計」といった要件になると、`filter` 集計や複数の集計を組み合わせて、ファセットごとに適用するフィルタを変える設計になります。まずは「query＝全ファセット共通の絞り込み、post_filter＝一覧だけの追加絞り込み」という基本形を押さえておけば、応用の見通しが立ちます。

> **コラム：terms 集計の精度と size**
> terms 集計の `size` は「返すバケット数の上限」です。複数シャードに分かれた大規模インデックスでは、各シャードの上位だけを集めて合算する仕組み上、件数に誤差が出ることがあり、`doc_count_error_upper_bound` で誤差の上限が示されます。学習用の single-node・少量データでは実質問題になりませんが、本番でロングテールなカテゴリを正確に数えたいときは `size` を十分大きくする、といった配慮が要ります。

---

## まとめ

- 集計は `_search` 内の `aggs` に書き、**クエリで絞った文書集合**に対して計算される。`size: 0` でヒットを省き集計だけ取得できる。
- **メトリック集計**（avg / min / max / sum / stats / cardinality）は数値を1つの値に要約する。
- **バケット集計**（terms / range / histogram）は文書をグループに振り分ける。terms がファセットの主役。
- 集計に使うフィールドは **`keyword`**（`text` は fielddata が必要で既定無効）。`category` / `tags` を keyword にしておいた理由がここで効く。
- バケットの中にメトリックを**入れ子**にすると「カテゴリ別の平均価格」などが取れる。
- `query` と `aggs` を同時に書けば**ファセット検索**になる。`post_filter` を使うと、集計は広い集合で計算しつつ、一覧だけを追加で絞れる。

## 理解度チェック

**Q1.** 集計だけが欲しくてヒット文書は不要なとき、どうしますか。

<details><summary>解答</summary>

リクエストに `"size": 0` を付けます。`hits` は空になり、`aggregations` だけが返ります。
</details>

**Q2.** メトリック集計とバケット集計の違いを一言で。

<details><summary>解答</summary>

メトリック集計は数値を**1つの値に要約**する（平均・合計など）。バケット集計は文書を**グループに振り分ける**（カテゴリ別・価格帯別など）。バケットの中にメトリックを入れ子にできる。
</details>

**Q3.** `category`（keyword）ではなく `description`（text）に terms 集計をかけるとどうなりますか。

<details><summary>解答</summary>

`text` はアナライザーで分割されるうえ、集計には `fielddata` が必要で既定で無効なため、エラーになるか、有効化しても大量のメモリを消費します。集計には `keyword` を使うのが原則です。
</details>

**Q4.** 「防水」で検索した結果の中で、カテゴリ別件数と価格の統計を同時に出すには？

<details><summary>解答</summary>

`query` に `match`（防水）を、同じリクエストの `aggs` に `terms`（category）と `stats`（price）を書きます。集計はクエリで絞られた集合に対して計算されるので、「防水の中での内訳・統計」になります。
</details>

**Q5.** ユーザーがカテゴリを選んだとき、一覧はそのカテゴリだけに絞り、ファセットの件数は他カテゴリも残したい。どうしますか。

<details><summary>解答</summary>

`post_filter` を使います。集計（aggs）は post_filter 適用**前**の集合で計算されるため他カテゴリの件数が残り、ヒット一覧だけが post_filter で絞られます。
</details>
